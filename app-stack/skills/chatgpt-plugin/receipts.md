# chatgpt-plugin: receipts

Each heading is a rule from `SKILL.md`, with the case that taught it.

## Verify the plugin against directory requirements before its first submission.

- `Undated`: Two products' submissions: a live Q&A product that submitted a plugin with no sign-in (rejected once, then resubmitted), and a monitoring product preparing one behind OAuth. They appear here only as examples.

- `Undated`: A mismatch with the legal pages was a rejection reason.

## Authentication is declared in `mcp.json`, per server, before the first upload.

- `2026-10`, an anonymous server whose first package declared nothing was taken for OAuth, signed in, and only a new plugin undid it.

## Every request's `params` may carry `_meta`, and the server accepts it.

- `2026-10-27`, twelve keys on one OAuth connector's call.

- `Undated`: A parser that refuses unknown keys there would refuse every one of those calls; one product's did, found in its code before any ChatGPT call.

## The privacy policy names every field a reply returns.

- `2026-10`, a policy that summarized was a rejection reason.

## Try a corrected ZIP first after a package rejection.

- `2026-10-19`, OpenAI support called a rejected plugin that could not be updated a known issue, with a new plugin as the fallback.
