# agent-instructions: receipts

Each heading is a rule from `SKILL.md`, with the case that taught it.

## Use the entry file to route every session's context.

- `Undated`: It was learned on SaaS repositories built with coding agents on Next.js + Supabase + Clerk + Netlify — a starter repository and the products built from it — and on a content repository run day to day by agents, whose instructions had grown to hundreds of thousands of words of doctrine.

## Give every reviewer a fallback, never “none”.

- `2026-11-06`, owner: a reviewer always has a fallback, never "none"; the pass rewrites "a model never reviews its own family's work" as *prefer another family*, with a fresh session of the builder's family when no other can run.

## After installing packs, record choices, a docs index and their router rows once.

- `2026-11-06`, a live Q&A product built before a billing rule: reading the rule against the code found both reads it forbids while every unit test passed; its development instance then confirmed that every API-token and MCP call from a paid workspace had been getting the free plan's AI allowance.

## Every new task opens its rows again.

- `2026-10-29`, the owner's call: a content repository run by agents already reloaded its matching files after every compaction, and once a session was not enough.

## File a rule at the fire point, not at its topic home.

- `2026-08-07`, a content repository: a rule governing a drafting-time decision was filed in the strategy file, loaded only in strategy sessions; the owner had to ask "when is strategy read?" before it moved.

## Script repeated product work and route each command from the entry file.

- `2026-11-05`, a remote-control product: its production smoke, auth canary, update-feed and UI checks are scripts beside its tests, each with its command.


## Each instruction and area file has a word budget, held by a check that runs.

- `2026-10-25`, a content repository run by agents: its rules had grown to about 330,000 words that no session could read, rules competed for attention and almost none was ever removed. It was rebuilt with a word budget per file, a checker and a write-time hook.

## Ask whether compliance depends on memory at the decisive moment before encoding a rule.

- `Undated`: In one agent-run repository the evidence was one-sided — everything implemented as code worked, everything implemented as a prose obligation decayed — and its sharpest instance was a two-line code bug answered with a convention, which killed a scheduled job for five days five weeks later.

## Keep status in the plan and at most three entry-file lines.

- `Undated`: A live Q&A product's status section grew until it was most of the file every session reads, and had to be moved out at least four times in four days.

## Keep a repository's own skills general, with products as examples named by kind.

- `2026-10-23`: Owner's rule.
