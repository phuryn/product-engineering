# Work without code

A pricing study, vendor evaluation, migration plan or set of user interviews uses the same two files
and owner's page. Set the area's `kind` to `other`. Keep RESUME first: the working folder, a branch
if there is one, recent sessions, and the instruction to read `STATUS.md` before resuming.

RUNNING NOW lists drafts, research or other runs underway, where each lives, and what each waits on.
QUEUED is the next work in order. BLOCKED names the missing input and who can supply it. HELD is
finished work awaiting a decision to use or share it. AWAITING holds only the owner's asks. DONE
records outcomes. EVIDENCE holds measured results, their source and date, including a result that
ruled an option out. STANDING RULES holds the constraints a new session needs.

Project the phase and done/now/next lines from those sections. The board holds 5 to 10 key work
items, such as comparing offers or testing a pricing assumption. A blocked card's note names what
it needs and from whom; an ask for the owner still belongs in `items`, where they can answer it.
`LOG.md` records decisions, changes of approach and why. Omit process ids or build steps when none
exist; verify the drafts, sources and runs the status actually names.
